## C. 方法分类地图

### 1. Post-training Compression

训练好 3DGS 后再压缩。

代表论文：
- LightGaussian
- Mobile-GS 的部分压缩模块

重点问题：
- 如何判断 Gaussian 重要性？
- 剪枝后是否需要 recovery fine-tune？
- SH / feature_rest 如何降阶或量化？

### 2. Training-time Pruning

训练过程中边训练边剪枝。

代表论文：
- Prune Wisely

重点问题：
- 什么时候剪？
- 每次剪多少？
- 剪完如何恢复细节？

### 3. Densification / Growth Control

训练过程中控制 Gaussian 怎么增长。

代表论文：
- FastGS 的 VCD
- Improving Densification
- Perceptual-GS
- PSCD-GS
- Neural Gabor Splatting 的 frequency-aware densification
- N-Dimensional Gaussians 的 Optimization-Controlled Refinement

重点问题：
- 哪些区域需要更多 Gaussian？
- 边缘、高频、残差区域是否应该优先加点？
- 是只决定“加不加”，还是还要决定 clone/split 与子点位置？
- 怎样避免 Gaussian 数量过早爆炸？

### 4. SH / Attribute Compression

压缩颜色、SH、feature_rest、opacity、scale、rotation 等属性。

代表论文：
- LightGaussian
- Mobile-GS
- Robust3DGSW 可作为量化参考

重点问题：
- 哪些属性可以量化？
- 哪些属性最好直接保留？
- 高阶 SH 是否可以蒸馏到低阶 SH？

### 5. Primitive Enhancement

增强单个 Gaussian 的表达能力，让更少 primitive 表达更多细节。

代表论文：
- Prune Wisely 的 3D-DoG
- Neural Gabor Splatting

重点问题：
- aggressive pruning 后为什么细节掉？
- 能不能让保留下来的 Gaussian 表达边缘、纹理、高频颜色？

### 6. Anchor / Compact Representation

从表示结构上减少冗余。

代表论文：
- 3DGS at Arbitrary Resolutions with Compact Proxy Anchors
- Scaffold-GS

重点问题：
- 能否不直接存所有 Gaussian？
- 能否存少量 anchor，再预测或生成剩余结构？

### 7. Feed-forward / Initialization

用模型直接预测几何、camera、depth、Gaussian 或组织结构。

代表论文：
- Z-Order Transformer
- VGGT / S-VGGT 可作为相关背景

重点问题：
- 是否减少 per-scene optimization？
- 是否能作为 COLMAP/SfM 或训练初始化替代？
- 是否能提供空间分组、抽帧、视角选择启发？

### 8. Avatar-specific GS

人体/Avatar 专用 Gaussian 表示。

代表论文：
- ExAvatar
- SFGS
- HumanSplatHMR
- HyperGaussians

重点问题：
- human Gaussian 是否需要 topology-aware / region-aware？
- 手、脸、关节区域是否应保护？
- SMPL / SMPL-X 和 Gaussian 之间应该强绑定还是松耦合？

### 9. Sparse-view Geometry / Depth Prior

在观测稀少或单目条件下，用外部几何线索约束 Gaussian 的位置与占据。

代表论文：
- DNGaussian

重点问题：
- 单目深度只有相对尺度，怎样与渲染深度对齐？
- depth loss 应该更新 position、opacity，还是连 scale/rotation 一起更新？
- 动态视频中如何处理逐帧 scale/shift 漂移、遮挡与低置信度深度？

### 10. High-dimensional / Dynamic Representation

把位置、视角、时间、表情、材质或局部 latent 放进联合高维表示。

代表论文：
- N-Dimensional Gaussians
- HyperGaussians

重点问题：
- 高维 Gaussian 如何参数化、条件化并高效 cull？
- 时间或表情变化应改变 position、scale、rotation 中的哪些属性？
- 表达能力增加后，如何避免参数、显存与条件计算成本失控？
- 能否把 uncertainty / temporal persistence 用于动态 VCP 或 density control？

# D. 单篇论文方法卡片

## 01. LightGaussian: Unbounded 3D Gaussian Compression with 15x Reduction and 200+ FPS

来源：[Project Page](https://lightgaussian.github.io/)

### 基本信息

```text
年份/会议：NeurIPS 2024 Spotlight
所属分类：C / S / Q
方法阶段：训练后压缩 + recovery fine-tune
对我重要性：★★★
```

### 解决的问题

原始 3DGS 在复杂场景中会从 SfM 稀疏点增长到百万级 Gaussian，导致单场景 checkpoint 很大、存储成本高、带宽和渲染效率受影响。直接按 opacity 剪枝太粗糙，容易误删对视角、边缘或背景有贡献的 Gaussian。

### 核心方法

1. Global Significance Score
   - 不只看 opacity，而是看 Gaussian 在所有训练视角、所有像素射线中的实际渲染贡献。
   - 重要因素包括 hit count、opacity、transmittance、volume。

2. Gaussian Pruning + Co-adaptation
   - 根据全局重要性分数排序，删掉低分 Gaussian。
   - 剩余 Gaussian 不再 densification，而是 fine-tune attributes 来恢复质量。

3. SH Distillation
   - teacher 使用完整高阶 SH。
   - student 使用低阶 compact SH。
   - 用真实训练视角和 pseudo-view 做像素级蒸馏，尽量保留 view-dependent 高光和反光。

4. Vector Quantization
   - 主要对低重要性 SH 系数做 VQ。
   - 位置、旋转、scale、opacity 等敏感属性通常保留更高精度。

### Pipeline

```text
Train vanilla 3DGS
↓
Compute global significance for each Gaussian
↓
Prune low-significance Gaussians
↓
Fine-tune remaining Gaussians for recovery
↓
Distill full SH teacher to compact SH student
↓
Apply VQ to selected low-significance SH attributes
↓
Store compact model
```

### 关键 score / 公式要记什么

```text
GS_j ≈ Σ over all training pixels:
hit(G_j, ray_i) × opacity_j × transmittance × volume_factor
```

理解重点：
- hit count：这个 Gaussian 被多少训练像素/射线看到。
- opacity：它本身透明度高不高。
- transmittance：前面有没有别的 Gaussian 挡住它。
- volume：它覆盖范围大不大，==但要归一化，避免背景大 Gaussian 被过度高估。==

### 实验要记

```text
关注指标：
Size / FPS / PSNR / SSIM / LPIPS / Gaussian 数量

核心结论：
能达到约 15x 压缩，同时 FPS 提升到 200+，质量损失较小。
```

### Ablation 结论

- 只剪枝会损失质量，recovery fine-tune 很重要。
- 直接降低 SH degree 会损失高光/反光，distillation 能明显恢复。
- VQ 要选择性做，对所有属性一刀切量化会损失精度。

### 局限

- 计算全局 significance 需要遍历训练视角和像素，成本不低。
- 主要是 general 3DGS 压缩，没有直接考虑 semantic / object / edge-aware。
- 对动态 Avatar / human Gaussian 迁移时，需要考虑 SMPL-X topology。

### 对我的启发

```text
可直接复现：
significance pruning + recovery fine-tune

可借鉴：
SH 降阶、pseudo-view distillation、低重要性 SH VQ

可能创新：
在 LightGaussian score 中加入 edge / semantic / human-region 权重。
```

## 02. FastGS: Training 3D Gaussian Splatting in 100 Seconds

来源：[Project Page](https://fastgs.github.io/) ｜ [CVPR 2026 Paper](https://openaccess.thecvf.com/content/CVPR2026/html/Ren_FastGS_Training_3D_Gaussian_Splatting_in_100_Seconds_CVPR_2026_paper.html) ｜ [Code](https://github.com/fastgs/FastGS)

### 基本信息

```
年份/会议：CVPR 2026 Highlight
所属分类：C / S / T
方法阶段：训练阶段的 densification + pruning + rasterizer 加速
对我重要性：★★★★★
```

`C` 表示 Compression/Capacity Control，`S` 表示 Selection，`T` 表示 Training Acceleration。

### 解决的问题

原始 3DGS 的主要训练瓶颈不是单次渲染慢，而是训练过程中 Gaussian 会持续 densify：

```
训练早期不断 clone / split
↓
Gaussian 数快速膨胀
↓
每个 view 的投影、tile pair、排序、alpha blending 都更贵
↓
训练后期大量 Gaussian 已冗余，但仍参与前向和反向传播
```

许多加速方法只在训练后剪枝，或者靠固定 Gaussian budget 限制数量。但这会出现两类问题：

- 太早限制数量，细节不够、质量下降；
- 太晚剪枝，前面已经付出了大量无效训练成本。

FastGS 的核心目标是：根据 Gaussian 的多视角一致性，决定哪些点值得继续 densify，哪些点应该尽早删除，从训练过程本身控制容量。

### 核心方法

#### 1. Multi-view Consistent Densification, VCD

原始 3DGS 的 densification 往往依赖单视角的 2D position gradient。问题是：一个 Gaussian 在某一张训练图上梯度大，不代表它在其他视角真的缺少几何/外观表达。

FastGS 用多视角一致性筛选 densification 候选：

```
一个 Gaussian 在多个相机视角中
都表现为误差大 / 投影不稳定 / 覆盖不足
↓
认为它是“真实需要细化”的点
↓
允许 clone 或 split
```

直觉上：

- 单视角梯度高，可能是噪声、遮挡或特定视角的局部现象；
- 多视角一致地需要细化，更可能对应真实几何或高频外观；
- 因此可以减少无效 clone/split，抑制 Gaussian 数爆炸。

#### 2. Multi-view Consistent Pruning, VCP

VCP 在训练中定期识别低价值 Gaussian 并删除。论文的关键不是简单 `opacity < threshold`，而是利用多视角渲染行为评估其贡献。

可以把它理解为：

```
一个 Gaussian 如果在多数训练视角中：
- 很少可见
- 常被前景遮挡
- 对像素颜色影响很弱
- 与其他 Gaussian 高度冗余
↓
它更适合被删除
```

这让 pruning 与 densification 形成闭环：

```
VCD：把容量给真正欠拟合的区域
VCP：回收跨视角持续低价值的区域
```

#### 3. Compact Box

Compact Box 是 FastGS 的 rasterizer 侧加速模块。它通过更紧的有效支持范围，减少 Gaussian 对像素/tile 的无效影响区域。

概念上：

```
原始 Gaussian 投影范围较宽
↓
同一个 Gaussian 覆盖更多 tile / pixel
↓
产生更多 Gaussian-tile pairs 和 blending 计算

Compact Box：
只保留足够有贡献的紧凑区域
↓
降低无效覆盖与 rasterization 开销
```

它不是减少模型总点数，而是减少某次渲染中“这个 Gaussian 需要参与多少 tile/pixel”的范围。

### Pipeline

```
Initialize 3DGS from SfM points
↓
Train and collect multi-view statistics
↓
VCD:
only densify Gaussians with multi-view-consistent need
↓
VCP:
prune Gaussians with consistently low multi-view value
↓
Use Compact Box to reduce rasterization overhead
↓
Finish training with controlled Gaussian capacity
```

### 关键 score / 机制要记什么

```
单视角梯度大
≠
这个 Gaussian 一定需要 split
```

FastGS 的关键是多视角一致性。它把“是否需要新增容量”与“是否需要删除容量”都从单视角局部判断，提升为跨视角判断。

对 VCP，可以理解为如下概念分数：

```
PruneScore(G_j)
≈ low visibility
+ low rendered contribution
+ high occlusion / redundancy
+ low multi-view consistency
```

不是所有实现都公开成一个固定公式；更重要的是它以多视角渲染统计驱动训练期的容量调控。

### Tile / Bucket 与 FastGS 的关系

FastGS 使用 tile-based rasterizer。对于一张图：

```
Gaussian
↓ 投影
Gaussian-tile pair
↓ 深度排序
tile 内 pair list
↓ 每 32 个 pair 分成一个 bucket
↓
renderCUDA alpha blending
```

你现在记录的几个指标对应：

```
num_rendered
= Gaussian-tile pairs 总数

num_buckets
= tile 内 pair list 按固定 bucket 容量分块后的总 bucket 数

pairs_per_bucket
= num_rendered / num_buckets
```

这些不是最终可见 Gaussian 总数，而是 rasterizer 实际需要处理的工作量。

### 实验要记

```
论文关注：
Training Time / PSNR / SSIM / LPIPS / Gaussian Count / GPU Memory

论文主张：
静态场景可约 100 秒完成训练；
相对不同 baseline 有约 2-7x 的训练加速；
在一些基准上相对 vanilla 3DGS 可达到更大的训练加速。
```

论文实验覆盖静态重建、动态场景、稀疏视角、表面重建、大场景和 SLAM，强调框架可迁移性。[FastGS Project Page](https://fastgs.github.io/)

### Ablation 结论

- 只做 densification 控制，不能充分回收冗余容量；
- 只做 pruning，可能过早删除潜在有用点；
- VCD 与 VCP 联合，才形成“生成有效点 + 删除冗余点”的容量闭环；
- Compact Box 是 rasterizer 侧辅助加速，不替代训练期 Gaussian 容量控制。

### 局限

- 多视角统计本身有额外计算成本；
- 方法效果与当前训练视角分布有关，极稀疏视角时“多视角一致性”证据会减弱；
- Compact Box 的 pair 减少不一定稳定转化为端到端 FPS，取决于 GPU、kernel、pair 数量和其他框架开销；
- VCD/VCP 改变了训练历史，因此不能只用最终 pruning score 的局部比较解释全部收益。

### 对我的启发

```
已经复现并扩展：
FastGS VCP + Global Light-T；
压力感知 Quota100 selector；
严格固定每轮删除量和最终 Gaussian 数。

当前关键发现：
低压力时，opacity 候选足够，换 score 改变很小；
强压缩时，低-opacity 候选不足，Quota100 + Light-T 的 score fill 才真正接管删除预算。

后续质量方向：
从“VCP 中换 score”升级为 residual-guided reallocation：
删掉冗余 Gaussian 后，
将等量容量通过 VCD clone/split 放到多视角高残差区域。

后续速度方向：
你的 clean raster-core profile 表明 renderCUDA 约占 50%；
应优先探索 FlashGS 类的 size-aware task partitioning，
而不是先投入 radix sort 优化。
```

## 03. Speeding Up the Learning of 3D Gaussians with Much Shorter Gaussian Lists

来源：[arXiv](https://arxiv.org/abs/2603.09277) ｜ [Code](https://github.com/MachinePerceptionLab/ShorterSplatting)

### 基本信息

```
常用简称：ShorterSplatting
年份/会议：2026，CVPR 2026 相关工作
所属分类：T / R / L
方法阶段：训练期的 Gaussian list 缩短
对我重要性：★★★★★
```

`T` 表示 Training Acceleration，`R` 表示 Rasterization Efficiency，`L` 表示 Loss/Regularization。

### 解决的问题

即使总 Gaussian 数不变，3DGS 的渲染成本也可能很高。

因为一个像素沿视线会有一个深度排序后的 Gaussian list：

```
pixel ray
↓
G1, G2, G3, ..., GN
↓
逐个计算 alpha、transmittance、blending
↓
前向渲染 + 反向梯度
```

如果每个像素/tile 的 list 很长：

- alpha blending 操作变多；
- 内存访问增多；
- 反向传播更重；
- training iteration 更慢。

论文的核心观点是：

```
总 Gaussian 数量
不等于
真实 rasterization 工作量
```

因此它不主要依赖删更多 Gaussian，而是让每个 Gaussian 更聚焦于它真正主导的像素区域，使每条 ray 上需要参与 alpha blending 的 Gaussian 更少。

### 核心方法

#### 1. Scale Reset

论文定期将所有 Gaussian 的 scale 按比例缩小：

```
s_i ← ζ × s_i
其中 ζ < 1
```

含义是：

```
Gaussian 更小
↓
覆盖更少附近像素 / tile
↓
更少进入这些像素的 Gaussian list
↓
list 变短
```

它不是永久把模型“压扁后不管”，而是：

```
Scale Reset
↓
继续训练若干 iteration
↓
position / opacity / SH / rotation / scale 继续共同优化
↓
逐渐恢复有效的辐射场表达
```

论文强调 reset 之间要有足够的优化窗口，让属性重新适配。它还观察到 reset 后通常会形成较小 scale 与较高 opacity 的表示。

#### 2. Entropy Constraint

对于某个像素，按深度排序的 Gaussian 权重为：

```
w_i(p) = T_i(p) × α_i(p)  它对最终像素真正贡献了多少
```

其中：

```
α_i(p) = opacity_i × projected_gaussian_i(p)  Gaussian 自己在该像素的 alpha

T_i(p) = Π over k<i (1 - α_k(p))  光线到达它之前还剩多少
```


```
σ：Gaussian 自己整体有多不透明
g(p)：它在这个像素位置还剩多强
α(p)：它此刻对该像素实际挡住/贡献多少
w=Tα：考虑前方遮挡后，它最终真正贡献多少
```
还要把背景残余透射率作为最后一个概率：

```
w_bg(p) = T_final(p)
```

于是：

```
Σ_i w_i(p) + w_bg(p) = 1
```

这很重要，因为它使权重天然构成概率分布，不需要额外归一化。

逐像素 entropy：

```
H(p) = - Σ_i w_i(p) log w_i(p)
       - T_final(p) log T_final(p)
```

总体 entropy loss：

```
L_entropy = mean over pixels of H(p)

L_total = L_photo + γ × L_entropy
```


最小化 entropy 后：

```
原本：
一个像素由很多 Gaussian 以小权重共同解释

Entropy 后：
少数主导 Gaussian 权重更大
大量次要 Gaussian 权重更小
↓
每个 Gaussian 更集中服务于自己的主要区域
↓
对邻近像素的弱影响减少
↓
Gaussian list 变短
```

这不是“直接删除 Gaussian”，也不是单独压低 opacity；它通过可微 alpha blending 改变 position、scale、opacity、rotation 等属性的联合优化方向。

#### 3. Resolution Scheduler（会影响VCD）

论文把 Scale Reset 和 Entropy 放进渐进分辨率训练：

```
低分辨率训练
↓
较少 pixel / 更便宜的 rasterization
↓
逐步提高训练分辨率
↓
在后期恢复高频细节
```

它的作用是进一步减少早期训练成本，与更短 Gaussian list 互补。

### Pipeline

```
Initialize 3DGS / LiteGS
↓
正常训练与 densification
↓
周期性 Scale Reset
↓
每一轮在 alpha blending 中计算 entropy loss
↓
继续优化，让属性在 reset 后重新适配
↓
按预设阶段提升训练分辨率
↓
得到相同或相近 Gaussian 数量，
但每个 pixel/tile 的 Gaussian list 更短的模型
```

### 关键公式要记什么

```
w_i = T_i α_i
T_i = Π_{k<i}(1 - α_k)
w_bg = T_final

H = -Σ_i w_i log(w_i) - w_bg log(w_bg)

L = L_photo + γL_entropy
```

理解重点：

- Entropy 约束的是沿一条 ray 的混合权重分布；
- 背景的 residual transmittance 也必须纳入 entropy；
- 不必显式归一化，因为 Gaussian 权重加背景权重天然和为 1；
- 它不是逐 Gaussian 的“重要性分数”，而是逐像素、逐 ray 的可微正则化。

### 实验要记

```
关注指标：
Training Time
PSNR / SSIM / LPIPS
Gaussian list length distribution
每 tile / 每 pixel 的 list length heatmap
Inference FPS

论文主张：
主要靠缩短 list，而非仅减少 Gaussian 总数；
在 Mip-NeRF 360 等基准中保持相近质量并显著缩短训练时间。
```

论文展示中，示例场景训练时间从原始 3DGS 的约 `919.51 s`、LiteGS 的约 `191.17 s` 降到方法的约 `99.58 s`；这是示例而非所有场景的统一常数。[ShorterSplatting paper](https://www.alphaxiv.org/abs/2603.09277)

### Ablation 结论

- `Scale Reset` 单独使用：直接缩小空间覆盖，立刻降低 list 长度；
- `Entropy` 单独使用：使权重更尖锐，弱化次要 Gaussian 对邻域像素的影响；
- `Scale Reset + Entropy`：几何上的覆盖收缩与权重分布收缩互补；
- 仅对 opacity 施加极化/二值化约束不如 entropy，因为 entropy 同时通过渲染权重作用于 opacity、scale、position、rotation；
- 单纯改变 tile size 不一定有效：tile 更小会让每 tile list 更短，但 tile 数变多，整体训练时间可能相近。

### 局限

- Scale Reset 的时机、缩放比例和下一次 reset 前的恢复窗口很敏感；
- 若 reset 与激进 pruning 在同一 iteration 发生，模型可能没有机会修复属性，质量会明显受损；
- Entropy 可能改善 LPIPS/SSIM 与 list 长度，却带来小幅 PSNR 代价；
- 额外的 entropy forward/backward 实现必须保持高效，否则正则化本身会抵消部分速度收益；
- 论文的 list 定义常更接近 per-pixel/per-tile workload；不同 rasterizer 的 `num_rendered`、bucket 和像素 list 不能混为同一个绝对量。

### 对我的启发

```
已成功融合：
在 FastGS rasterizer 中实现可微 alpha-blending entropy：
H(p) = -Σ_i w_i log(w_i) - T_final log(T_final)

训练损失：
L = L_photo + FASTGS_ENTROPY_LAMBDA × mean(H)

当前最佳强压缩配置：
Quota100 + Global Light-T + Entropy λ=.020

最强证据：
Truck, keep=.53, final points=166,360, 两个共同 recovery seed：
PSNR  +0.0461 dB
SSIM  +0.00202
LPIPS -0.00323
rendered P95 -16.3%
```

```
已经证实的机制：
Entropy 让 keep=.53 的 raster-core 总时间下降 12.2%，
其中 renderCUDA 下降 17.1%。

当前不应夸大的地方：
Entropy 是训练期表征重分配；
它不直接决定 Quota100 删除哪些点。
它会改变低-opacity 候选池，因此 selector 与 entropy 的组合收益
应表述为融合结果，不能完全归因给 selector。
```

```
Scale Reset 当前结论：
FastGS 中同步执行 “Scale Reset f=.20 + VCP prune”
导致质量显著下降。

这不等于否定 ShorterSplatting 原文：
原文 reset 后有继续训练与属性修复窗口；
你当前实验把 reset 与固定强剪枝事件绑定，存在明显混杂。
因此该分支应冻结，未来若重做，必须：
reset 和 prune 错开；
reset 后保留恢复窗口；
单独测 reset，再测 reset + entropy。
```

```
下一步最值得做：
1. 跨场景复现 keep=.53 的 Quota100 + Light-T vs + Entropy .020；
2. 使用两个共同 recovery seed；
3. 报告质量、Gaussian 数、rendered mean/P95、bucket mean/P95、
   raster-core 时间和 Pure FPS；
4. 将 Entropy 与 FlashGS 类 renderCUDA 调度融合，
   因为 Entropy 已经缩短输入 list，而 renderCUDA 仍是主瓶颈。
```





## 04. Prune Wisely, Reconstruct Sharply

来源：[CVPR 2026 Open Access](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_Prune_Wisely_Reconstruct_Sharply_Compact_3D_Gaussian_Splatting_via_Adaptive_CVPR_2026_paper.html)

### 基本信息

```text
年份/会议：CVPR 2026
所属分类：P / E / G
方法阶段：训练中 adaptive pruning + compact model recovery
对我重要性：★★★
```

### 解决的问题

3DGS 为了高质量会产生大量 primitive。剪枝能减少冗余，但如果剪得太早、太多或只看简单指标，会导致细节损失。普通 Gaussian 在 compact 数量下表达边缘和纹理能力有限，所以 aggressive pruning 后边缘容易糊。

### 核心方法

1. Reconstruction-aware Pruning Scheduler
   - 根据重建质量决定剪枝时机。
   - 不是固定 interval 机械剪枝，而是看模型是否已经恢复到可以继续剪的状态。

2. Adaptive Pruning Ratio
   - 不同阶段剪枝比例不同。
   - 避免早期过度剪枝，也避免后期压缩不足。

3. Pruning Score
   - 不只考虑 opacity。
   - 融合空间和频率/细节相关信息，保护更重要的结构区域。

4. 3D Difference-of-Gaussians Primitive
   - 一个 3D-DoG = primary Gaussian - pseudo Gaussian。
   - 形成中心正密度峰和周围负密度环。
   - 更适合表达边缘、边界和高频细节。

5. 3D-DoG Density Control
   - 不是所有 DoG 永远保留。
   - pseudo Gaussian 贡献很低时退化回普通 Gaussian，减少额外开销。

### Pipeline

```text
Train 3DGS
↓
Monitor reconstruction state
↓
Adaptive pruning scheduler decides pruning time
↓
Compute pruning score
↓
Prune low-score Gaussians
↓
Convert compact model primitives to 3D-DoG
↓
Fine-tune recovery
↓
Control DoG density, unnecessary DoG degenerates to normal Gaussian
```

### 关键点要记

```text
这篇不是只回答“删谁”，而是同时回答：
1. 什么时候删？
2. 每次删多少？
3. 根据什么删？
4. 删完后少量 primitive 怎样恢复细节？
```

### 实验要记

```text
关注：
Gaussian count reduction
Model size
FPS
PSNR / SSIM / LPIPS
不同剪枝率下质量什么时候明显下降
```

### Ablation 结论

- scheduler 能避免过早/过度剪枝。
- 更合理的 pruning score 能保护重要细节。
- 3D-DoG 对 aggressive pruning 后的边缘和高频细节恢复很关键。

### 局限

- 3D-DoG 需要改 primitive 表示，工程难度比单纯 checkpoint 后处理高。
- 如果要迁移到 ExAvatar，需要考虑 human Gaussian 与 SMPL-X topology 的绑定。
- 对你当前阶段，完整复现可能偏重。

### 对我的启发

```text
可直接借鉴：
adaptive pruning schedule、high-frequency/detail-aware pruning score

暂时不急着做：
完整 3D-DoG primitive

可能创新：
把 Prune Wisely 的 reconstruction-aware 思想与 LightGaussian significance、edge-aware score、semantic mask 结合。
```

## 05. Improving Densification in 3D Gaussian Splatting for High-Fidelity Rendering

来源：[CVPR 2026 Findings Open Access](https://openaccess.thecvf.com/content/CVPR2026F/html/Deng_Improving_Densification_in_3D_Gaussian_Splatting_for_High-Fidelity_Rendering_CVPRF_2026_paper.html) ｜ [Official Code / Improved-GS](https://github.com/XiaoBin2001/Improved-GS)

### 基本信息

```text
年份/会议：CVPR 2026 Findings
所属分类：D / E / G
方法阶段：训练中 densification 改进
对我重要性：★★★
```

`Improved-GS` 是这篇论文的官方代码仓库名称，不是一篇需要重复建卡的新论文。代码中的 EAS、LAS、RAP、Growth Control / Multi-view Update 分别对应下述 densification 与过拟合控制模块。

### 解决的问题

原始 3DGS 的 densification 主要依赖 2D view-space gradient 来决定 clone / split。这个策略容易：
- 漏掉边缘和高频区域；
- split 方式随机，破坏几何；
- Gaussian 数量增长过快；
- 训练后期过拟合单视角。

### 核心方法

1. Edge-Aware Score
   - 用 Laplacian edge map 找图像边缘。
   - Gaussian 如果投影到边缘像素且贡献大，就更应该 split。

2. Absolute Gradient
   - 避免正负梯度抵消。
   - 更真实地反映某个区域是否还存在重建误差。

3. Long-Axis Split
   - 沿 Gaussian 最长轴分裂。
   - 比随机 split 更符合原始椭球几何，减少扰动。

4. Recovery-Aware Pruning
   - opacity reset 后观察哪些 Gaussian 恢复慢。
   - 恢复慢的点更可能是 floater / artifact，优先剪掉。

5. Growth Control
   - 给 Gaussian 数量增长设置预算曲线。
   - 防止训练早期点数爆炸。

6. Multi-view Update
   - densification 后期用多视角更新，增强泛化。

### Pipeline

```text
Train 3DGS
↓
Compute absolute gradient
↓
Compute edge-aware score from 2D edge map and Gaussian contribution
↓
Select candidate Gaussians
↓
Apply long-axis split
↓
Use recovery-aware pruning to remove unreliable Gaussians
↓
Control Gaussian growth budget
↓
Multi-view update after densification stage
```

### 最重要的迁移点

```text
Edge-Aware Score 可以从 densification 迁移到 pruning：
边缘贡献大的 Gaussian 不应该轻易剪。
```

### 实验要记

```text
关注：
PSNR / SSIM / LPIPS
Gaussian 数量
训练开销
是否有额外 inference overhead

核心结论：
在更少 Gaussians 下提升 rendering fidelity，
且不增加额外训练或推理开销。
```

### Ablation 结论

- Edge-Aware Score 提升细节和 LPIPS。
- Long-Axis Split 提升几何稳定性。
- Recovery-Aware Pruning 减少 floater。
- Growth Control 避免过早过密。

### 对我的启发

```text
可直接借鉴：
Edge-Aware Score
Recovery-Aware reliability 判断

可能创新：
在 LightGaussian / opacity pruning 中加入 edge protection：
importance = render contribution + edge contribution + residual contribution
```

## 06. Mobile-GS: Real-time Gaussian Splatting for Mobile Devices

来源：[GitHub / arXiv 信息](https://github.com/xiaobiaodu/Mobile-GS)

### 基本信息

```text
年份/会议：ICLR 2026
所属分类：M / C / Q / R
方法阶段：移动端渲染系统 + 压缩
对我重要性：★★☆
```

### 解决的问题

3DGS 在桌面 GPU 上能实时，但移动端受限于：
- depth sorting 成本高；
- alpha blending 难并行；
- Gaussian 数量多；
- 属性存储和显存带宽高。

### 核心方法

1. Depth-aware Order-independent Rendering
   - 传统 3DGS 需要严格按深度排序再 alpha blending。
   - Mobile-GS 试图消除或弱化排序瓶颈，提高移动端并行效率。

2. Quantization
   - 压缩 Gaussian 属性，降低内存和带宽。

3. Contribution-based Pruning
   - 减少 Gaussian 数量。
   - 删除视觉贡献低的 primitive。

4. Mobile-friendly system design
   - 目标不是只让文件小，而是真正在手机/边缘设备上跑得快。

### Pipeline

```text
Train / pretrain compact 3DGS
↓

↓
```

## 09. Z-Order Transformer for Feed-Forward Gaussian Splatting

来源：[CVPR 2026 Open Access](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_Z-Order_Transformer_for_Feed-Forward_Gaussian_Splatting_CVPR_2026_paper.html)

### 基本信息

```text
年份/会议：CVPR 2026
所属分类：F / Z
方法阶段：feed-forward Gaussian prediction
对我重要性：★★
```

### 解决的问题

传统 3DGS 需要每个场景慢慢 optimization。Feed-forward GS 希望从输入图像直接预测 Gaussian attributes，但 Gaussian 是无序点集，Transformer 很难高效建模空间关系，而且 Gaussian redundancy 仍然存在。

### 核心方法

1. Z-order Serialization
   - 用 Morton / Z-order 把无序 Gaussian 按空间连续性排成序列。
   - 近邻空间点在序列中也更接近。

2. Sparse Attention
   - 在 Z-order 序列上做稀疏注意力。
   - 降低 Transformer 处理大规模 Gaussian 的成本。

3. Z-order Pooling / Redundancy Suppression
   - 利用空间序列做聚合和压缩。
   - 尽量保留结构细节，减少冗余 primitive。

### Pipeline

```text
Input images
↓
Feed-forward network predicts initial Gaussian set / features
↓
Z-order organizes Gaussians into spatial sequence
↓
Sparse Transformer models context
↓
Pooling suppresses redundant Gaussians
↓
Predict Gaussian attributes in one forward pass
```

### 对我当前实验的结论

你已经尝试过 Z-order local scene pruning：
- checkpoint 从约 769M 降到 719M；
- 前景基本不变；
- 但 global opacity prune25 质量更接近 baseline；
- Z-order 当前更多是辅助空间组织工具，不适合作为主线创新。

### 对我的启发

```text
可借鉴：
空间分块、局部统计、抽帧或区域聚合。

不建议强行做：
把 Z-order 当作压缩核心创新。

可能保留方向：
Z-order + 更强 score，例如 edge / residual / semantic score。
```

## 12. HumanSplatHMR: Closing the Loop Between Human Mesh Recovery and Gaussian Splatting Avatar

来源：[arXiv](https://arxiv.org/abs/2605.02784)

### 基本信息

```text
年份：2026 arXiv
所属分类：H / G / Sem
方法阶段：HMR + Gaussian Avatar 联合优化
对我重要性：★★☆
```

### 解决的问题

Human Mesh Recovery 关注人体 mesh / pose 准确，但渲染外观不一定好；Gaussian Avatar 关注渲染质量，但常把 pose 和 appearance 分开处理，依赖预先准确的 SMPL/SMPL-X。如果初始人体姿态估计有误，Avatar 会被错误 pose 带偏；如果 Gaussian 太自由，又可能脱离人体 mesh，在训练视角上过拟合。

### 核心方法

1. Closing the Loop
   - 不把 HMR 输出的 SMPL pose 当作固定输入。
   - 通过 differentiable rendering 的 photometric / segmentation / depth loss 反向优化 pose 和 global position。

2. CAMEL: Cloth-Aware Mesh-Embedded Loss
   - 让 Gaussian 和人体 mesh 保持松耦合。
   - 不是强迫所有 Gaussian 死贴 mesh，也不是完全自由脱离。
   - 允许衣服厚度和局部非刚性，但保持几何一致。

3. Mesh Coverage Loss
   - 保证人体 mesh 被 Gaussian 覆盖，避免某些身体区域缺点。

4. Gaussian Flatness Regularization
   - 鼓励 Gaussian 更扁、更贴近人体表面。

5. Surface Alignment Loss
   - 鼓励 Gaussian 最小轴和 mesh normal 对齐。

6. Depth and Mask Supervision
   - 使用 UniDepthV2 提供 metric depth。
   - 使用 SAMv2 生成人体 mask。
   - 用 depth/mask 帮助 pose 和 geometry 对齐。

### Pipeline

```text
Input monocular RGB video
↓
HMR2.0 estimates initial SMPL pose
↓
SAMv2 gives human mask
↓
UniDepthV2 gives metric depth
↓
Initialize Gaussians on / near SMPL mesh
↓
Render color and depth through differentiable renderer
↓
Backprop photometric + segmentation + depth + CAMEL losses
↓
Jointly refine SMPL pose/global position and Gaussian attributes
↓
Output better mesh pose and higher-quality avatar rendering
```

### 实验要记

```text
Datasets：
H36M, 3DPW, NeuMan

Metrics：
SMPL accuracy: MPJPE, PA-MPJPE, V2V
Rendering: PSNR, SSIM, LPIPS

重要结论：
相比只用 HMR 或 decoupled avatar，HumanSplatHMR 同时提升 pose alignment 和 novel-view rendering。
```

### Ablation 结论

- 不优化 SMPL，pose 和渲染都会受影响。
- 去掉 depth loss，global 3D alignment 变差。
- learnable skinning weights 可提高渲染，但可能让 Gaussian 脱离 mesh，损害 SMPL accuracy。
- CAMEL 在 rendering quality 和 SMPL accuracy 之间取得更好平衡。

### 对我的启发

```text
可借鉴：
mask / depth supervision 可以帮助 Gaussian 与人体结构对齐。

用于压缩：
可把 SAM mask / human region / depth consistency 用作 Gaussian importance prior。

可能创新：
human-aware pruning：
根据 Gaussian 是否位于人体 mask、边界、衣服区域、关节附近，设置不同剪枝强度。
```

## 13. DNGaussian: Optimizing Sparse-View 3D Gaussian Radiance Fields with Global-Local Depth Normalization

来源：[CVPR 2024 Open Access](https://openaccess.thecvf.com/content/CVPR2024/html/Li_DNGaussian_Optimizing_Sparse-View_3D_Gaussian_Radiance_Fields_with_Global-Local_Depth_CVPR_2024_paper.html) ｜ [Official Code](https://github.com/Fictionarry/DNGaussian)

### 基本信息

```text
年份/会议：CVPR 2024
所属分类：Dep / G / L
方法阶段：少视角 3DGS 训练中的深度正则化
对我重要性：★★★★★
```

### 解决的问题

输入视角变少后，RGB 重建损失不足以约束真实几何，同一组训练图像可能对应多种错误的 Gaussian 深度分布。普通 3DGS 仍可能在训练视角上拟合颜色，但在新视角出现漂浮点、空洞和几何错位。

直接把单目伪深度施加到 Gaussian 的全部属性也不理想。伪深度通常较平滑且只有相对尺度，如果让 scale 和 rotation 一起强行拟合它，Gaussian 会牺牲原本用于表达细纹理的形状，导致外观变糊。

### 核心方法

1. Shape Freezing
   - 深度正则化时冻结 scale `s` 和 rotation `q`。
   - 将位置 `mu` 与 opacity `alpha` 视为几何重塑的主要变量。
   - 目的不是让椭球形状迎合粗糙深度，而是移动 Gaussian 中心、调整空间占据。

2. Hard Depth Regularization
   - 渲染 hard depth 时，把沿射线的 Gaussian 使用统一较大 opacity `tau`。
   - 前面的 Gaussian 会迅速遮挡后面的 Gaussian，因此 hard depth 主要由最近表面决定。
   - 此阶段重点更新 Gaussian center，使位置错误的 primitive 真正移动，而不能靠变透明或变形逃避约束。

3. Soft Depth Regularization
   - 普通 alpha blending 的深度是多个 Gaussian 按 `T_i alpha_i` 加权后的 soft depth。
   - 仅修正最近表面仍可能留下半透明或空心结构，所以 soft 阶段冻结 center，重点调整 opacity。
   - Hard 管“表面位置”，Soft 管“沿射线的真实占据与透明度”，两者作用不同。

4. Global-Local Depth Normalization
   - 单目深度没有可靠绝对尺度，不能直接与渲染深度逐值比较。
   - Local normalization 在小 patch 内用该 patch 的均值和标准差归一化，放大小范围深度起伏。
   - Global normalization 保留全图尺度信息，防止模型只关注局部变化而丢掉整体形状。
   - 两种归一化共同用于 hard / soft depth loss。

### Pipeline

```text
Sparse posed RGB images
↓
Use a pretrained monocular depth estimator to obtain pseudo depth
↓
Initialize and optimize 3D Gaussians with RGB reconstruction loss
↓
Freeze Gaussian scale and rotation during depth regularization
↓
Hard depth loss: mainly move Gaussian centers
↓
Soft depth loss: mainly adjust opacity while center is fixed
↓
Apply local and global depth normalization
↓
Continue RGB/depth joint optimization and render novel views
```

### 关键 score / 公式要记什么

```text
Soft depth:
D_soft(p) = Σ_i distance(mu_i, camera) × alpha_i(p) × T_i(p)

Local normalization:
D_LN(x) = [D(x) - mean(D(P))] / [std(D(P)) + eps]

Global normalization:
D_GN(x) = [D(x) - mean(D(P))] / [std(D_image) + eps]
```

理解重点：
- `Hard depth` 强调最前面的表面，用于修正 center。
- `Soft depth` 保留真实 alpha compositing，用于修正 opacity 与占据。
- `Local` 让细小深度变化不会被大尺度范围淹没。
- `Global` 维持整体几何关系。
- depth 在这里是训练 loss，不是 edge detector，也不是直接的 pruning score。

### 实验要记

```text
数据集：LLFF / DTU / Blender
输入：3 / 6 / 9 views 等 sparse-view 设置
指标：PSNR / SSIM / LPIPS / training time / rendering speed / memory

论文主张：
相对当时的 sparse-view radiance-field baselines，
训练时间约减少 25x，渲染速度可超过 3000x，
同时保持有竞争力的少视角新视角合成质量。
```

注意：这些倍率的比较对象主要是 sparse-view NeRF 类方法，不能直接解释成比 FastGS 快 25 倍或 3000 倍。

### Ablation 结论

- 只使用普通的全参数 depth loss 容易损伤纹理，shape freezing 很关键。
- Hard depth 能推动错误位置的 Gaussian 移动，但单独使用不能充分修复透明度和空洞。
- Soft depth 补充真实 compositing 下的 opacity 约束。
- Local normalization 对局部几何细节重要，Global normalization 负责整体结构；二者是互补关系。

### 局限

- 依赖单目深度估计质量，反光、透明和纹理缺失区域可能产生错误监督。
- 研究对象是静态 sparse-view 场景，不直接解决动态视频。
- 动态视频中不同帧的单目深度可能有独立的 scale/shift 漂移，不能逐帧直接套用。
- 额外深度模型推理和 depth loss 也会增加预处理与训练成本。

### 对我的启发

```text
可直接借鉴：
把 depth 定义为 geometry supervision，明确它更新哪些属性；
对伪深度先做 scale-invariant 的 global/local alignment。

与 FastGS 的结合位置：
RGB loss + depth loss 共同训练；
depth residual 可辅助 Dynamic VCD 判断哪里几何欠拟合，
但不能未经实验就直接塞进 VCP importance。

当前 M3 假设：
Dynamic FastGS + Feed-forward initialization + Robust depth loss
是否能在 equal-time 下提高几何与渲染质量，
或在 equal-quality 下更早收敛。

动态扩展必须新增：
per-frame scale/shift alignment、depth confidence、
temporal consistency 与运动/遮挡 mask。
```

## 14. Perceptual-GS: Scene-adaptive Perceptual Densification for Gaussian Splatting

来源：[arXiv](https://arxiv.org/abs/2506.12400) ｜ [Official Code](https://github.com/eezkni/Perceptual-GS)

### 基本信息

```text
年份/会议：ICML 2025
所属分类：D / Per / E / L
方法阶段：训练中 perception-aware densification
对我重要性：★★★★☆
```

### 解决的问题

vanilla 3DGS 主要按 view-space position gradient 增密，无法显式区分“人眼敏感的局部结构”和“视觉上不重要的平滑区域”。结果可能是简单区域 Gaussian 冗余，而树叶、道路纹理、细边界等区域仍然模糊。

直接使用 Sobel 响应强度也有问题：强轮廓数值很大，较弱但人眼可见的细纹理容易被掩盖。因此论文不是简单把 edge magnitude 加到 gradient，而是先建立可学习的 3D perceptual sensitivity 表示。

### 核心方法

1. Perceptual Sensitivity Extraction
   - 对训练 RGB 图像使用 Sobel 提取梯度幅值。
   - 用阈值把响应二值化，表达“能否被感知”，降低绝对边缘强度差异的影响。
   - 再通过平均池化和阈值平滑，得到每个视角的 sensitivity map。

2. Dual-branch Rendering
   - 每个 Gaussian 新增一个可学习 sensitivity 参数 `epsilon_i`。
   - RGB branch 正常渲染颜色；sensitivity branch 用同一组 alpha blending 权重渲染 sensitivity。
   - 用 BCE 让渲染 sensitivity map 对齐预计算的二值 map，使 2D 感知信息真正落到 3D primitive 上。

3. Perceptual Sensitivity-guided Densification
   - warm-up 后将 Gaussian 分为 high、medium 和 low sensitivity。
   - high 表示持续位于人眼敏感区域；medium 往往表示一个 Gaussian 跨多个不同 sensitivity 区域，单个 primitive 表达范围过大。
   - 还要求 Gaussian 的最大多视角 rendering weight 超过阈值，避免只凭 sensitivity 无限制加点。
   - 高/中 sensitivity 点被额外 densify；大多数情况优先 split，只有低 scene-sensitivity 场景中的 high 组允许 clone。

4. Scene-adaptive Depth Reinitialization
   - 统计 warm-up 后“大 scale 且 medium sensitivity”的比例 `gamma`。
   - 比例高说明 SfM 初始点云可能太稀疏，较大的 Gaussian 正在跨区域勉强覆盖。
   - 仅在 `gamma` 超过阈值时触发 depth reinitialization，避免所有场景都付出相同代价。

5. Opacity Decline for Clone
   - vanilla clone 会复制 opacity，使同一区域总 opacity 突然升高，冗余 child 之后更难被剪掉。
   - 论文在 clone 时降低 parent/child opacity，尤其更强地压低原本低 opacity 的 clone，让无用点更容易被后续 pruning 清除。

### Pipeline

```text
Training RGB views
↓
Sobel gradient → threshold enhancement → pooling/smoothing
↓
Precompute binary perceptual sensitivity maps
↓
Warm-up 3DGS with RGB branch + sensitivity branch
↓
Learn one sensitivity value for each Gaussian
↓
Select high/medium sensitivity Gaussians with rendering-weight constraint
↓
Scene-adaptive clone or split + opacity decline
↓
If sparse-initialization indicator is high, apply depth reinitialization
↓
Continue ordinary 3DGS optimization and pruning
```

### 关键 score / 公式要记什么

```text
Sensitivity rendering:
R_S^v(u) = Σ_i w_i^v(u) × sigmoid(epsilon_i)

Training loss:
L = (1 - lambda_S) L_RGB + lambda_S L_BCE(sensitivity)

Candidate constraint:
G_D = {high or medium sensitivity Gaussians}
      ∩ {max multi-view rendering weight > threshold}
```

Opacity decline 的核心约束：两个重叠 clone 的合成 opacity 应等于一个主动降低后的目标值，而不是简单复制后使区域更不透明。

### 实验要记

```text
数据集：Mip-NeRF 360 / Tanks & Temples / Deep Blending / BungeeNeRF
关注：PSNR / SSIM / LPIPS / Gaussian 数量 / FPS

Mip-NeRF 360 平均消融表：
3DGS*：27.71 PSNR / 0.826 SSIM / 0.202 LPIPS / 3.14M
Full： 28.01 PSNR / 0.839 SSIM / 0.172 LPIPS / 2.69M
```

这组数字支持的是“在论文协议下获得更好的质量-点数平衡”，不能直接推成在 FastGS 的 100 秒预算下仍有相同收益。

### Ablation 结论

- 去掉 perception-oriented enhancement 后，质量接近 vanilla 3DGS，说明不能只依赖原始 Sobel 强度。
- 去掉 high-sensitivity densification 后性能明显下降，high 组是主要质量来源。
- 去掉 medium-sensitivity densification 后仍优于 baseline，但细节恢复变弱。
- 去掉 scene-adaptive depth reinitialization 的影响较小，说明它是场景条件模块而非核心主因。
- Dual-branch rendering 不只是传递标签，也会抑制 low-sensitivity 区域的 gradient 与 densification。

### 局限

- sensitivity 主要是图像感知先验，不等同于真实 3D geometry boundary。
- 二值阈值、high/medium 分组、事件间隔等超参数较多。
- 额外 sensitivity 参数和渲染分支增加训练复杂度。
- 论文主要验证静态场景；动态视频中的纹理运动、遮挡和时间闪烁尚未处理。

### 对我的启发

```text
最直接的结合点是 FastGS VCD，而不是先改 VCP：
FastGS 负责多视角一致的“是否需要容量”；
Perceptual-GS 提供“这部分容量对人眼是否值得”。

候选实验：
先由 FastGS VCD 得到候选，
再用 sensitivity 只调整候选优先级或固定预算内的名额，
严格保持 densification event、净增长量与训练时间协议可比。

不能直接宣称：
edge-aware pruning 已由此证明有效；
论文验证的是训练期容量分配，不是训练后剪枝。

动态迁移：
把单帧 sensitivity 升级为 temporal-consistent sensitivity，
否则快速运动纹理可能被误判并产生 flicker。
```

## 15. PSCD-GS: Role-Aware Perception-Structure Collaborative Densification for 3D Gaussian Splatting

来源：用户提供的本地 PDF `PSCD_GS_for_3D_Gaussian_Splatting__1_ (1).pdf`

### 基本信息

```text
年份/会议：2026 manuscript；PDF 未标明正式录用 venue，引用时需再次核验
所属分类：D / Per / Str / V
方法阶段：训练中 role-aware densification
对我重要性：★★★★☆
```

### 解决的问题

只用 gradient 只能说明“当前优化压力大”，不能说明欠拟合来自纹理、结构边界还是二者共同作用。只加一个 perceptual 或 edge score 也不足以回答 densification 的三个不同问题：

```text
1. 哪个 Gaussian 需要新增容量？
2. 新增容量应该 clone 还是 split？
3. split 后的 child 应该放在哪里？
```

PSCD-GS 因此把 perception 与 structure 分开建模，再用连续角色同时协调三个决策。

### 核心方法

1. Perceptual Evidence `P`
   - 用冻结的 ImageNet VGG-16 / LPIPS 特征提取多尺度 feature variation。
   - 得到感知响应强度图和主要图像方向 tensor。
   - 这部分更关注纹理与外观变化，训练前可预计算。

2. Structural Evidence `Q`
   - 由 luminance gradient 与当前渲染 `log-depth gradient` 共同形成单视角结构响应。
   - 把像素反投影到相邻相机，比较深度与结构响应的一致性。
   - 多视角一致性在这里是 reliability gate：它决定单视角边界可信多少，而不是凭空制造结构分数。

3. Contribution-weighted Gaussian Aggregation
   - 使用 renderer 的真实贡献 `w_i^v(u)=T_i^v(u) alpha_i^v(u)`，把 2D P/Q map 聚合到每个 Gaussian。
   - 再根据跨视角支持数和方差衰减“只在一个弱视角出现”或“多视角互相矛盾”的证据。
   - 用随 densification event 更新的分位数范围校准为 `P_i, Q_i ∈ [0,1]`。

4. Continuous Perception-Structure Roles
   - 分别将 `P_i`、`Q_i` 经过 sigmoid，得到软 membership。
   - 四种角色为 co-dominant、perception-dominant、structure-dominant、low-response。
   - 它们不是硬语义标签；同一个 Gaussian 可以在训练中连续改变角色。

5. Role-conditioned Densification
   - Candidate priority：保留原始 gradient demand，再让 P/Q evidence 提供有限 bonus，并受每次净增长预算约束。
   - Clone-or-split：perception-dominant 更偏向 clone，structure-dominant 更偏向 split；大 scale 仍强制 split。
   - Split placement：把多视角 2D 响应方向通过 projection Jacobian 提升到 Gaussian 支持域中的 3D 方向，再沿可靠方向对称放置 children；置信度不足时回退到主轴或 vanilla 随机采样。

### Pipeline

```text
Precompute VGG perceptual maps, image boundaries and camera-neighbor graph
↓
Ordinary 3DGS training accumulates view-space gradient
↓
At each densification event, render current depth
↓
Build perceptual P maps and multi-view reliable structural Q maps
↓
Aggregate P/Q to Gaussians with T × alpha contribution
↓
Compute four continuous role memberships
↓
Fixed growth budget: select candidates
↓
Role-conditioned clone/split decision
↓
Confidence-aware child placement
↓
Return to original optimization, pruning and opacity-reset loop
```

### 关键 score / 公式要记什么

```text
Per-pixel contribution:
w_i^v(u) = T_i^v(u) × alpha_i^v(u)

Gaussian-level evidence:
x_i^{X,v} = Σ_u w_i^v(u) X^v(u) / [Σ_u w_i^v(u) + eps]
where X is perceptual map A or structural map B

Candidate priority:
D_i = G_i + alpha_bonus × (1 - G_i) × S_i
```

其中 `G_i` 是由原始 view-space gradient 得到的 optimization demand，`S_i` 是由连续 P/Q 角色得到的 evidence bonus。这里没有用 P/Q 替代 gradient，而是让证据在受控范围内重新排序候选。

### 实验要记

```text
数据集：Mip-NeRF 360 / Deep Blending / Tanks & Temples
指标：PSNR / SSIM / LPIPS / final Gaussian count

Full model 的三组 benchmark-level ablation 数值：
Mip-NeRF 360：28.2439 / 0.8396 / 0.1814
Deep Blending：30.2961 / 0.9184 / 0.2243
Tanks & Temples：24.5968 / 0.8815 / 0.1407
顺序：PSNR / SSIM / LPIPS
```

论文报告 Mip-NeRF 360 约 2.8M Gaussians，并强调质量导向的受控增长；它不是以最少点数或最快训练为第一目标。

### Ablation 结论

- Mip-NeRF 360 上，去掉 joint candidate selection 对 PSNR/SSIM 影响最大；去掉 perceptual branch 对 LPIPS 影响明显。
- Deep Blending 同样依赖 perceptual evidence 与 joint candidate selection。
- Tanks & Temples 上 structural branch 最重要，符合其物体轮廓、遮挡边界和细结构较多的特点。
- 去掉 soft role、role-adaptive clone/split、role-guided placement 都会退化，说明“在哪加、怎么加、加到哪”是连续但不同的决策。

### 局限

- VGG 特征、深度刷新、多视角重投影和 contribution tensor 统计增加训练开销，PDF 未把该开销与 FastGS 级别的总训练时间系统比较。
- 依赖当前渲染深度和跨视角对应；少视角、反光、运动与遮挡会削弱结构 reliability。
- 主要验证静态场景，动态和在线重建尚未验证。
- soft role 与决策仍含多组固定阈值，跨场景鲁棒性需要额外复核。
- 当前 PDF 的正式发表状态不明确，投稿引用前必须核验最新版本。

### 对我的启发

```text
它给我的最大启发不是“再加两个 score”，而是拆开三项决策：
where to densify / clone or split / where to place children。

与 FastGS 的结合：
FastGS VCD 先提供多视角一致的 gradient demand；
PSCD 的 P/Q role 只在固定增长预算内重排候选并决定操作；
这样不会绕开 FastGS baseline 的核心机制。

动态扩展假设：
P = perceptual / appearance evidence
Q = geometry / depth evidence
R = temporal persistence / motion reliability
用 P-Q-R role 驱动 Dynamic VCD。

注意：
P-Q-R 是我的研究假设，不是 PSCD-GS 已经证明的结论。
第一步应先做小规模 P/Q 插件消融，统计额外 wall-clock 开销。
```

## 16. HyperGaussians: High-Dimensional Gaussian Splatting for High-Fidelity Animatable Face Avatars

来源：[CVPR 2026 Paper](https://openaccess.thecvf.com/content/CVPR2026/html/Serifi_HyperGaussians_High-Dimensional_Gaussian_Splatting_for_High-Fidelity_Animatable_Face_Avatars_CVPR_2026_paper.html) ｜ [Project Page](https://gserifi.github.io/HyperGaussians/) ｜ [Official Code](https://github.com/gserifi/HyperGaussians)

### 基本信息

```text
年份/会议：CVPR 2026
所属分类：ND / Dyn / H / G
方法阶段：动态 Avatar 的 primitive 表示层
对我重要性：★★★★★
```

### 解决的问题

许多人脸 Avatar 方法使用 MLP 根据表情或姿态直接预测每个 Gaussian 的 position、scale、rotation offset。这样的映射缺少每个局部 Gaussian 自己的上下文，容易把眼睛高光、眼镜反射、牙齿缝隙、皱纹和眼睑闭合等高频动态效果平均掉。

简单加宽或加深 deformation MLP 不一定能解决问题，而且会显著降低 FPS。HyperGaussians 的思路是从 primitive 参数化本身增加表达力：让 Gaussian 属性与一个局部 latent 共同组成高维联合 Gaussian，再根据当前表情生成的 latent 对属性做条件化。

### 核心方法

1. Attribute-Latent Joint Gaussian
   - 将某一类 3DGS 属性 `A` 与局部 latent `z` 建模为联合多元 Gaussian。
   - 属性可以分别是 position offset、scale offset 或 rotation offset。
   - 联合 covariance 的交叉块学习“latent 怎样影响该属性”。

2. Conditional Gaussian to Ordinary 3DGS
   - 当前表情/姿态经过原 avatar 网络，不再直接输出属性 offset，而是输出 per-Gaussian latent `z`。
   - 对联合 Gaussian 计算 `p(A | z)`，取条件均值作为当前帧的 position/scale/rotation offset。
   - 条件化后仍得到普通 3D Gaussian，所以后端可继续使用标准 differentiable rasterizer。

3. Separate Conditional Position, Scale and Rotation
   - 与早期 NDGS 主要依赖 position 的条件分布不同，HyperGaussians 分别让 position、scale、rotation 随 latent 改变。
   - 这使 Gaussian 在动态形变中不仅能移动，还能旋转和缩放，更适合眼睑、嘴部和皱纹等非线性局部变化。

4. Bayesian Interpretation and Uncertainty
   - 条件均值等价于 Gaussian 条件分布的 MAP 解。
   - 条件 covariance 不直接参与 splatting，但可解释为属性的不确定性。
   - 注意：论文证明了这种不确定性可被计算，不等于已经用它完成 pruning。

5. Inverse Covariance Trick
   - 朴素条件化需要存储和求逆大的 latent covariance block `Sigma_bb`，latent 维数高时很贵。
   - 论文改用 precision matrix `Lambda = Sigma^{-1}`，只需处理较小的属性 block `Lambda_aa` 和交叉 block `Lambda_ab`。
   - 复杂度从 `O(n^3 + m n^2)` 降为 `O(m^3 + m^2 n)`；结合 Cholesky 还可进一步降低。

6. Plug-in Integration
   - 在 FlashAvatar 中，把 deformation MLP 的 `delta position/rotation/scale` 输出改为 latent 输出。
   - 在 GaussianHeadAvatar 中做相同替换。
   - 其余训练 loss、renderer 和大部分超参数保持不变，用来证明提升来自 primitive 表示，而非整体重写网络。

### Pipeline

```text
Monocular or multi-view face video
↓
Track 3DMM/FLAME pose and expression; attach Gaussians to mesh
↓
Avatar deformation network predicts a local latent z for every Gaussian
↓
Condition high-dimensional joint Gaussians on z
↓
Obtain ordinary 3D position / scale / rotation offsets from conditional means
↓
Construct current-frame 3D Gaussians
↓
Use standard Gaussian splatting and original avatar losses
```

### 关键 score / 公式要记什么

```text
Standard conditional mean:
mu_{a|b} = mu_a + Sigma_ab Sigma_bb^{-1} (z - mu_b)

Inverse covariance trick:
mu_{a|b} = mu_a - Lambda_aa^{-1} Lambda_ab (z - mu_b)

Conditional covariance:
Sigma_{a|b} = Lambda_aa^{-1}
```

最容易混淆的点：
- 这里的高维 covariance 描述“属性和 latent 的联合关系”。
- 渲染时的 3D spatial covariance 仍由条件化后的 scale 与 rotation 构造。
- 二者不是同一张 covariance matrix。

### 实验要记

```text
数据：6 个数据集、29 个 subjects
Monocular：19 subjects，512×512，FlashAvatar baseline
Multi-view：10 subjects，NeRSemble，GaussianHeadAvatar baseline

FlashAvatar → HyperGaussians：
PSNR 29.43 → 29.99
SSIM 0.9466 → 0.9510
LPIPS 0.05107 → 0.04978

GaussianHeadAvatar → HyperGaussians：
PSNR 24.10 → 24.38
LPIPS 0.20273 → 0.19768
```

`n=8` 是论文的人脸 Avatar 推荐 latent dimension；FlashAvatar 集成后约 300 FPS。FlashAvatar 每个视频在 RTX 4090 上约 15-20 分钟，而 GaussianHeadAvatar 仍需 600K iterations、超过 2 天，说明表示层更好并不自动等于所有 baseline 都训练很快。

### Ablation 结论

- 只把 deformation MLP 加深或加宽，质量不如 HyperGaussians，FPS 还从约 300 降到 158/178。
- `n=8` 在质量、参数量和速度之间最好；更高 latent dimension 参数量继续增加，但质量不再稳定提升。
- inverse covariance trick 在 `n=8` 时将朴素条件计算内存从约 42 MB 降到 22 MB；latent 越大，节省越明显。
- 在 GaussianHeadAvatar 中额外训练时间约增加 1%，说明高效条件化确实控制住了新增开销。

### 局限

- 主要验证人脸 Avatar，有 3DMM/FLAME、mesh attachment 和可靠表情跟踪先验，不等同于无模板通用动态场景。
- 高维表示仍增加参数、显存和条件计算，只是 inverse covariance trick 大幅缓解而非消除。
- 论文重点是高保真表达，不是 pruning、densification 或训练到 100 秒。
- 条件 uncertainty 没有被论文直接用于 VCP；把它当 pruning risk 需要重新验证。

### 对我的启发

```text
对当前动态主线的直接价值：
动态 Gaussian 不一定只是“3D Gaussian + deformation offset”；
primitive 自身的条件表达能力会决定细节是否需要靠大量增点补偿。

与 Dynamic FastGS 的潜在结合：
VCD 决定哪里需要新增动态容量；
HyperGaussian latent 负责在时间/表情变化下复用已有容量；
若单个高维 primitive 已能表达变化，可能减少重复 densification。

候选研究假设：
Dynamic VCP risk = rendering contribution
                   × temporal persistence
                   × uncertainty protection

其中 uncertainty protection 只是我的扩展设想。
必须先验证 uncertainty 高代表“必要但难预测”，
还是代表“噪声和不可靠”，两种解释的剪枝方向正好相反。
```

## 17. N-Dimensional Gaussians for Fitting of High Dimensional Functions

来源：[SIGGRAPH 2024 Project Page](https://sdiolatz.info/ndg-fitting/) ｜ [arXiv](https://arxiv.org/abs/2405.20067) ｜ [Official Code](https://github.com/intel/ndg-fitting)

### 基本信息

```text
年份/会议：SIGGRAPH 2024 Conference Track
所属分类：ND / Dyn / D / R
方法阶段：高维表示 + 训练中 refinement + 高维查询 culling
对我重要性：★★★★★
```

### 解决的问题

普通 3DGS 主要在 3D 空间中显式建模 geometry，再用 SH 表示视角相关颜色。若输入函数还依赖时间、视角方向、材质、粗糙度或光照位置，简单追加 feature 或使用 MLP 会带来两个问题：

- 高维 Gaussian 数量大时，逐查询评估所有 primitive 太慢；
- 维度越高，手工决定“沿哪一维 split、何时 split”越困难。

论文因此提出通用 N-D Gaussian mixture、随机投影 culling 和由 optimizer 自己激活容量的 refinement。

### 核心方法

1. Full N-D Gaussian Parameterization
   - 每个 Gaussian 有 `m ∈ R^N` 和完整 covariance `V ∈ R^{N×N}`。
   - 用 Cholesky factor `V = L L^T` 保证正定，并直接学习下三角矩阵。
   - 非对角项显式表达维度耦合，例如 position-view、position-time 或 position-material 的相关性。

2. Random-projection / LSH-inspired Culling
   - 将 query、Gaussian mean 和 covariance 投影到若干随机单位向量 `r`。
   - 若某个投影上 query 位于 Gaussian 的 3-sigma 区间之外，该 Gaussian 可被保守剔除。
   - 实现按 `16×16` tile 处理 query bounds，避免逐像素做全部高维判断。

3. Optimization-Controlled Refinement
   - 初始收敛后，每个 main Gaussian 挂一个贡献极低、相对 parent 参数化的 child。
   - child 的 mean/covariance 随 parent 一起移动，只有当前容量表达不了细节时，optimizer 才会提高 child 的 opacity/brightness 并让它与 parent 分离。
   - child 贡献超过阈值后被 materialize：parent 与 child 都成为独立 main Gaussian，并各自获得新的 dormant child。
   - 论文实现约每 300 iterations 检查一轮；opacity 应用示例阈值 0.1，brightness 应用示例阈值 0.01。

4. Parent-relative Child Geometry
   - parent covariance 为 `V_p = L L^T`。
   - child 使用局部变换 `U`：`V_c = L U (L U)^T`。
   - child mean 为 `m_c = L m_u + m_p`。
   - 这种依赖让 child 初期待在 parent 支持范围内，不会一开始就跑到无关区域重复拟合。

5. Two Applications
   - `10D+ surface radiance`：position、view、albedo、roughness 等共同作为输入，拟合复杂全局光照函数。
   - `6D volumetric radiance`：3D position + 3D view direction；给定视角后将 6D Gaussian 条件化/投影为 3D，再使用 3DGS rasterizer。

### Pipeline

```text
Normalize N-dimensional query space and initialize a small Gaussian mixture
↓
Optimize full N-D means, Cholesky factors and appearance/opacity
↓
Use random projections to cull irrelevant Gaussians per query tile
↓
After initial convergence, attach low-contribution child to each main Gaussian
↓
Optimizer raises only the children needed for missing details
↓
Materialize children that cross the contribution threshold
↓
Repeat refinement phases
↓
Evaluate directly in N-D or condition/project to 3D for splatting
```

### 关键 score / 公式要记什么

```text
N-D Gaussian:
G(x) = exp[-1/2 (x - m)^T V^{-1} (x - m)]
V = L L^T

Random projection:
q_r = q^T r
m_r = m^T r
sigma_r^2 = r^T V r

Cull when query lies outside the projected 3-sigma interval:
|q_r - m_r| > 3 sigma_r
```

阅读提醒：论文排版中的 Eq. (5) 印成了 `< 3 sigma`，但紧随其后的文字、图示和 culling 逻辑都说明应当是“落在区间外才剔除”，也就是 `>`。实现时不能照抄符号。

### 实验要记

```text
6D real-world radiance-field scenes：CD / Tools

PSNR：
CD：Ours 28.39 / 3DGS 25.76 / INGP 27.23
Tools：Ours 27.58 / 3DGS 26.32 / INGP 25.70

Gaussian count 与 Python-renderer inference：
CD：Ours 0.32M, 24.5 ms / 3DGS 1.01M, 62.92 ms
Tools：Ours 0.27M, 41.23 ms / 3DGS 1.36M, 70.57 ms
```

高维 culling 在论文的合成场景 profile 中把 brute-force inference 从约 317 ms 降到 131 ms，平均 Gaussian evaluations 从 7856 降到约 1985。这里是论文自有 Python/Taichi 实现，不能与 FastGS CUDA FPS 直接横比。

### Ablation 结论

- 3-sigma 是论文选择的质量-速度折中；继续压到 2-sigma 或 1.5-sigma 虽更快，但开始出现明显伪影。
- culling 同时减少 forward evaluation 与 backward propagation，因此训练和推理都受益。
- parent-relative child 约束很关键；无约束 child 容易离开 parent 并重复拟合。
- dormant child 让新增容量初始贡献近乎为零，避免传统突然 split 造成 loss spike。

### 局限

- 完整 N-D covariance 的参数量按 `O(N^2)` 增长。
- 高维拟合需要足够密集的训练采样；输入稀疏时更容易过拟合。
- 官方实现明确说明当前 refinement 不适合 360 度场景，依赖较好初始化或近似 front-facing capture。
- 论文展示的是视角/材质等高维函数，虽提到 time 维度，但没有直接完成通用单目动态重建。
- 其 Cholesky 表示与 FastGS 的 quaternion + scale 参数化不同，不能直接复制 child 公式。

### 对我的启发

```text
最值得迁移到 FastGS 的不是整套 N-D renderer，
而是 Optimization-Controlled Refinement：

FastGS VCD 先确定多视角/多帧一致的候选 parent
↓
给候选挂低-opacity soft child，而不是立即硬 split
↓
短窗口优化
↓
child contribution 达阈值才 materialize
↓
未被利用的 child 直接丢弃
```

这可能减少错误 split 和 densification 后的 loss spike，同时仍保留 FastGS 的候选选择与容量预算。

```text
动态扩展：
将 time 或 motion latent 作为额外维度，

在相同净增长数和相同训练时间下优于立即 clone/split。
```
